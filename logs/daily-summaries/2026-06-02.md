**Architectural notes / caveats**

- `SourceCache` is **in-process only** — cache resets on server restart and is not shared across multiple instances. If you scale horizontally, each instance has its own cache. Redis would be needed for multi-instance continuity.
- `session_id` is client-supplied via `X-Session-ID` header. There is no authentication on this header — any client can pass any session ID. If user isolation matters, tie session_id to an authenticated user token instead.
- `needs_fresh_retrieval=False` skips Pinecone entirely. If the planner mis-classifies a question (sets it to false when fresh retrieval was actually needed), the answer quality will degrade silently. Monitor for this in LangSmith traces.
- The `@traceable` decorator requires `LANGCHAIN_API_KEY` and `LANGCHAIN_TRACING_V2=true` in the environment. If these are absent, tracing is silently skipped — no errors.
- `po-dev-loop` agent requires the `agent` tool to invoke subagents. If subagent invocation is disabled in the VS Code settings, the loop will not function.
